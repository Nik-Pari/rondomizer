# Рондомайзер для Inter-СамПо

Офлайн-приложение для ротации пар на тренировках **West Coast Swing**. Один организатор открывает приложение на телефоне или ноутбуке, добавляет участников — а программа составляет пары на каждый танец.

- Работает без сервера, регистрации и интернета после первого открытия.
- Данные хранятся только в браузере устройства.
- Интерфейс и подсказки — на русском.
- Устанавливается на главный экран iPhone и Android как PWA.
- Умеет показать крупный экран для группы, отправить снимок вечера ссылкой, QR-кодом или JSON-файлом.

---

## Быстрый старт

Нужен [Node.js](https://nodejs.org/) 22.18+ (проект проверен на Node 24). Node 24 LTS предпочтителен: скрипты загружают конфигурацию Vite напрямую, без промежуточной сборки esbuild — это надёжнее на сетевых дисках и путях с кириллицей.

Затем в папке проекта:

```bash
npm install
npm run dev
```

Откройте адрес из терминала, обычно `http://localhost:5173/`.

Если `npm run dev` не запускается на сетевом диске (Vite не может следить за файлами), используйте сборку и предпросмотр:

```bash
npm run build
npm run preview
```

Предпросмотр откроется на `http://localhost:4173/`. Для проверки офлайна и установки лучше использовать именно собранную версию, а не dev-режим.

| Команда | Что делает |

| `npm run icons` | Перегенерирует PNG-иконки из `scripts/make-icons.mjs`. |

## Как пользоваться

1. Откройте вкладку **«Люди»** и добавьте лидеров и фоловеров. Можно по одному или списком — по одному имени в строке.
2. Проверьте роли и статусы. Если человек вышел на время — поставьте **«Отсутствует»**, если ушёл — **«Ушёл»**. Вернуть можно в любой момент.
3. На вкладке **«Танец»** нажмите **«Да начнутся Танцы! 💃🕺»** (вечером со второго раунда кнопка называется **«Составить пары»**).
4. При необходимости нажмите **«Поменять»** и поменяйте местами двух участников одной роли: пару с парой или пару с пропуском. Крестик **✕** у пары отправляет обоих участников в пропуск.
5. Покажите экран группе кнопкой **«На большой экран»** или значком глаза в шапке.
6. Подтвердите станцованные пары — см. следующий абзац. Только после подтверждения обновляются счётчики, история и круги.
7. Следующий раунд снова начинается с кнопки **«Составить пары»**.

### Подтверждение раунда по парам

Пара, которую не станцевали (опоздали, ушли, передумали), не должна «сгорать» вместе с раундом. Поэтому подтверждение работает поштучно:

1. Нажимайте на карточки пар, которые реально станцевали, — они подсветятся. Можно выбрать сразу несколько.
2. Нажмите **«Подтвердить выбранное · N»** — отмеченные пары уйдут в историю этого раунда, черновик останется.
3. Оставшиеся неподтверждённые пары после **«Подтвердить остальные · N»** считаются пропущенными раунд: они вернутся в следующий раз.
4. Когда подтверждены все пары, кнопка завершает раунд целиком.

Подтверждённые пары защищены: их нельзя сдвинуть обменом или крестиком, пока раунд не подтверждён целиком (отмена последнего раунда снимает отметки со всех). Счётчик **«подтверждено X из Y»** виден в шапке.

Последний подтверждённый раунд можно отменить один раз — кнопка **«Отменить последний раунд»**. Отмена откатывает и историю, и состояние кругов, и отметки пар.

### Важные понятия

- **Раунд** — один танец. Черновик раунда ещё не влияет на статистику.
- **Круг** — цикл, в котором участник танцует с разными партнёрами противоположной роли. Когда он станцевал со всеми активными партнёрами, его круг закрывается, список обнуляется, номер круга увеличивается. Номер круга **всегда пересчитывается из истории** раундов и текущего активного состава, поэтому не «съезжает» при уходах, возвратах и смене роли; загружаемый снимок («ссылка вечера») тоже починяется автоматически.
- **Пропуск** — участник из большей по числу активных роли, который в этом раунде остался без пары. Количество пропусков в раунде равно `|лидеры − фоловеры|`. Отдельные пары можно отправить в пропуск вручную (крестик в режиме «Поменять» или неподтверждение при подтверждении по парам).
- **Активные** — только они участвуют в ротации. «Отсутствует» и «Ушёл» остаются в списке и статистике, но не получают пары.

## Как работает подбор пар

**Первый раунд вечера — детерминированный.** i-й лидер танцует с i-m фоловером в порядке списков (как добавлены или загружены из снимка). Лишние участники более многочисленной роли (начиная с конца списка) пропускают. Кнопка **«Новый вечер»** сбрасывает историю — и снова даёт детерминированный первый раунд.

Со второго раунда включается обычный подбор по приоритетам, строгим сверху вниз:

1. **Равенство числа танцев внутри роли.** Разница не должна превышать один танец. Пропускают только участников из избыточной роли; в равном составе пропусков нет.
2. **Не повторять партнёра внутри текущего круга.** Если пары без повторов составить невозможно, повтор разрешается, но штрафуется.
3. **Не ставить одного и того же партнёра два раунда подряд**, если есть альтернатива. Пропуски тоже стараются распределять ровно: одному человеку не дают пропустить два раунда подряд, а при равном числе танцев в пару первым идёт тот, кто **дольше всех ждёт в текущем круге** — то есть чаще остальных пропускал именно в этом круге.
4. **Реже танцевавшие пары и давние встречи.** При равном числе совместных танцев предпочтение отдаётся паре, которая дольше не встречалась.

Для подбора используется венгерский алгоритм (поиск минимальной стоимости назначения) на расширенной матрице: к реальным парам добавляются фиктивные колонки/строки для пропусков. Это позволяет учитывать справедливость и подбор пар за один проход.

Вес штрафов настроен так, что справедливость пропусков стоит **ниже** правила «танцы равны внутри роли» и **выше** запрета на повтор партнёра в круге: сначала алгоритм не даёт никому отстать по числу танцев, потом старается закрыть круги без повторов, и только в рамках равных вариантов выбирает давнишних «ждущих».

### Когда приоритет 1 может пересилить приоритет 2

Так бывает, и это сделано специально:

- **Опоздавший или вернувшийся участник.** У него меньше танцев, поэтому штраф за его пропуск огромен. Программа поставит его в пару даже с тем, с кем он уже танцевал в текущем круге, если иначе ему пришлось бы пропустить.
- **Изменился состав или соотношение ролей.** В большей роли кому-то необходимо пропустить раунд. Если все варианты пропуска нарушают справедливость, возможен повтор в круге.
- **Маленькая группа.** Например, один лидер и один фоловер: круг закрывается после каждого раунда, поэтому пара повторяется каждый раз. Это не ошибка.
- **Нет варианта без повтора.** Если людей слишком мало или круг уже почти закрыт, алгоритм выбирает наименее болезненный вариант.

При равенстве ролей пропусков нет вообще, поэтому опоздавший не может «догнать» остальных, пока кто-то не уйдёт или роли не станут неравными. Это следствие правила «пропуск только в избыточной роли», а не сбой.

Ещё одна особенность: при разном числе лидеров и фоловеров возможны **односторонние** повторы в круге — когда круг сбросился у одного партнёра, а у другого ещё нет. Повтор считается допустимым, если хотя бы у одного из партнёров он не в текущем круге. Полностью «двойные» повторы в тестах отсутствуют, пока круг не закрыт у обоих.

## Установка на телефон

### Android / Chrome

1. Откройте сайт по **HTTPS** (или на `localhost`).
2. Нажмите меню `⋮` → **«Установить приложение»**.
3. Подтвердите установку.

В приложении на вкладке **«Ещё» → «Установить на телефон»** есть кнопка установки, если браузер её разрешил, и QR-код на текущий адрес.

### iPhone / iPad

1. Откройте сайт именно в **Safari**.
2. Нажмите **«Поделиться»** (квадрат со стрелкой вверх).
3. Выберите **«На экран „Домой“»**.
4. Нажмите **«Добавить»**.

### Почему нужен HTTPS

Service worker, офлайн-кэш и установка PWA работают только в защищённом контексте: по HTTPS или на `localhost`. По обычному `http://192.168.x.x` приложение откроется, но офлайн-режим не включится.

**Первый запуск должен быть с интернетом:** приложение скачает и сохранит все файлы. После этого сеть не нужна.

## Офлайн-режим и обновления

- При сборке генерируется `sw.js` со списком всех файлов и версией кэша.
- Все пути относительные, поэтому приложение работает и в корне домена, и в подпапке вида `/sub/folder/`.
- Навигация использует стратегию «сеть, затем кэш»: при наличии интернета открывается свежая версия, без сети — сохранённая.
- При обновлении появляется уведомление **«Доступно обновление приложения»**. Данные в localStorage при обновлении не удаляются.
- Если приложение уже открыто, обновление может примениться после перезагрузки.

### Как проверить офлайн

1. Соберите и откройте сайт по HTTPS или `localhost`.
2. Дождитесь полной загрузки и статуса «Офлайн-кэш активен» на вкладке **«Ещё»**.
3. В DevTools → Application → Service Workers убедитесь, что worker активен.
4. Включите режим Offline в DevTools (или выключите Wi-Fi) и обновите страницу.
5. Приложение должно открыться, данные — сохраниться.

Для проверки в подпапке разложите **содержимое** `dist/` в `/sub/folder/` и откройте `/sub/folder/` (со слешем в конце). Не загружайте саму папку `dist` как вложенную, если хотите открыть её по короткому адресу.

## Передача данных

Вкладка **«Ещё» → «Передать данные»**:

- **Ссылка со снимком.** Участники, история, круги и текущий черновик сжимаются в hash-часть URL. При открытии ссылки приложение предложит загрузить снимок. Текущие данные будут заменены только после подтверждения.
- **QR-код.** Ведёт на ту же ссылку. Если ссылка длиннее 1800 символов, QR не показывается — используйте копирование ссылки или JSON.
- **JSON-файл.** Скачивается и импортируется на другом устройстве. Это резервный способ, если ссылка слишком длинная или QR не читается.
- **Web Share.** На телефоне можно отправить ссылку через системное меню «Поделиться».

**Снимок — это не синхронизация.** Изменения на одном устройстве не появляются на другом автоматически. Чтобы обновить данные, отправьте новую ссылку или новый файл. Ссылка очищается из адресной строки после загрузки, чтобы старый снимок не загрузился случайно ещё раз.

Снимок содержит имена и историю танцев. В URL нет шифрования: любой, у кого есть ссылка, может прочитать данные. Передавайте её только тем, кому доверяете.

## Приватность и хранение

- Состояние хранится в `localStorage` браузера под ключом `rondomizer.state.v2`.
- Сохранение происходит после каждого действия. Отдельной кнопки «Сохранить» нет.
- Очистка данных сайта в браузере удалит и данные приложения.
- Приложение не отправляет данные на сервер, не использует аналитику и внешние CDN.
- В снимке по ссылке данные путешествуют в URL — это удобно, но не приватно.

Рекомендуется перед важным вечером скачать JSON-снимок: это резервная копия на случай очистки браузера.

## Сборка и публикация

### Обычная PWA

```bash
npm run build
```

Содержимое `dist/` — готовый статический сайт. Загрузите **содержимое** папки на любой статический хостинг:

- GitHub Pages;
- Netlify / Vercel (статические файлы);
- обычный nginx/Apache;
- корпоративный веб-сервер.

Маршрутизации на сервере не требуется: приложение использует только hash для снимков и не использует path-based routing. Все ассеты, manifest, иконки и service worker подключены относительными путями.

### ZIP

```bash
npm run package
```

Появится `release/rondomizer-pwa-1.0.0.zip`. Внутри — файлы из `dist/` в корне архива, включая `.nojekyll`.

### GitHub Pages

В проекте есть workflow `.github/workflows/deploy.yml`. Он собирает сайт и публикует `dist/` при push в `main`.

1. Создайте репозиторий и отправьте проект в ветку `main`.
2. В настройках репозитория: **Settings → Pages → Source → GitHub Actions**.
3. Дождитесь выполнения workflow.

Относительный `base: './'` позволяет работать и на `https://user.github.io/repo/`.

### Один HTML-файл для `file://`

```bash
npm run build:single
```

Появится `dist-single/index.html` — один самодостаточный файл, который можно открыть двойным щелчком, положить на флешку или отправить в мессенджере.

Что важно знать про single-file версию:

- она **работает** без интернета и без сервера;
- **не устанавливается** как PWA;
- **не использует** service worker и не кэширует обновления;
- manifest и иконки для установки в ней отключены;
- данные всё равно хранятся в localStorage браузера, но у `file://` могут быть ограничения браузера;
- для установки на телефон и полноценного офлайна используйте обычную сборку на HTTPS.

ZIP с одним файлом:

```bash
npm run package:single
```

## Тесты и симуляции

```bash
npm test
```

Тесты находятся в `src/core/rotation.test.ts` и проверяют:

- **a)** 5 лидеров × 5 фоловеров, 30 раундов: равенство танцев и отсутствие повторов в круге;
- **b)** 8 × 12, 50 раундов: разброс не больше 1, нет пропусков подряд и двойных повторов;
- **c)** 20 × 20 и 20 × 25: скорость генерации;
- **d)** 60 × 80, 20 раундов: работа на большом составе;
- **e)** уходы и возвращение участника;
- **f)** опоздавший догоняет остальных;
- **g)** переход от равного состава к перевесу лидеров;
- **h)** кодирование и декодирование снимка;
- частичное подтверждение раунда: отметки пар, «остальные» уходят в пропуск, обмен не трогает подтверждённые, из пропуска можно вытащить в неподтверждённую пару;
- согласованность кругов: загрузка снимка с «уехавшим» номером чинится, после ухода и возврата круги равны `deriveCircles`;
- справедливость пропусков: 6 × 5, 12 раундов — нет пропусков подряд, разброс ≤ 1;
- краевые случаи: нет одной роли, 1 × 1, undo, ручная перестановка, закрытие круга при уходе, новый вечер, создание кругов для новых людей.

Тесты печатают краткие сводки: число повторов, пропусков, разброс танцев и длину ссылки.

## Ограничения и допущения

- Один организатор и одно устройство как «источник истины». Облачной синхронизации нет.
- Роли только **лидер** и **фоловер**.
- В ротации участвуют только активные участники; отсутствующие и ушедшие сохраняются в истории.
- Пропуски возможны только в большей роли; их число равно разнице числа активных ролей.
- Отмена доступна на один последний подтверждённый раунд. Более глубокой истории отмен нет.
- Снимок не заменяет резервную копию в JSON, если браузер очищает хранилище.
- QR-код ограничен длиной ссылки; для длинных вечеров используйте JSON.
- Приложение не проверяет допустимость имён и может допускать одинаковые имена — это не запрещено.
- Импортированный снимок проходит базовую валидацию, но не является криптографически подписанным.
- `file://`-версия не является PWA и может иметь ограничения localStorage в зависимости от браузера.

## Если что-то не работает

**Пустая страница после загрузки на хостинг.** Проверьте, что в корень сайта загружено содержимое `dist/` (`index.html`, `assets/`, `icons/`, `manifest.webmanifest`, `sw.js`), а не сама папка `dist`.

**Приложение открывается, но не устанавливается.** Нужен HTTPS или `localhost`. На iPhone — Safari, не встроенный браузер мессенджера.

**Не появляется офлайн-режим.** Откройте DevTools → Application → Service Workers. Проверьте, что `sw.js` загружается без 404 и что первый запуск был при интернете.

**Не приходит обновление.** Закройте все вкладки приложения и откройте снова. Service worker обновляется при открытии и возврате на вкладку.

**Не сохраняются данные.** Проверьте свободное место и настройки браузера (приватный режим может запрещать localStorage). Приложение покажет уведомление об ошибке сохранения.

**QR-код не читается.** Слишком длинная ссылка. Скопируйте её или используйте JSON-файл.

**Dev-сервер падает с ошибкой watch на сетевом диске.** Это ограничение файловой системы, а не приложения. Используйте `npm run build && npm run preview`.

## Лицензия

Проект учебный и бытовой; сторонние библиотеки распространяются по своим лицензиям. Перед публикацией на своём домене проверьте условия используемых шрифтов и иконок — в проекте нет внешних шрифтов и CDN.
